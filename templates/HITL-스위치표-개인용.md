# 사람 개입 지점 워크시트 (개인용)

> 5회차 5교시. 오늘 내가 돌린 파이프라인의 실행 기록(콘솔·`output/`·`run_log.jsonl`)을 보면서 채운다. 7교시 운영 기준서의 "사람 개입 기준" 절에 그대로 옮겨 붙는다.

## 1. 오늘 실행에서 사람이 개입한 지점

실제로 내가 멈추고 확인한 곳에 체크하고, 무엇을 보고 무엇을 결정했는지 한 줄씩 적는다.

| 지점 | 언제 | 내가 본 것 | 내가 결정한 것 | 체크 |
|---|---|---|---|---|
| ⓐ 입력 확인 | 실행 전 | `=== 실행 전 점검 ===` 결과, 입력 JSON 내용 | 이 입력으로 돌려도 되는가 | [ ] |
| ⓑ 검수 FAIL 정지 | 함정 1건 실행 후 | 검수자의 지적 사항, 2연속 FAIL 정지 메시지 | 고쳐서 다시 돌릴지, 입력·위키를 보강할지, 버릴지 | [ ] |
| ⓒ PASS 후 승인 | 정상 1건 실행 후 | 리서치 리포트, 초안, 근거 표기 | 채택안으로 올릴지, 수정 요청할지 | [ ] |
| ⓓ 회수·발행 결정 | 승인 뒤 | 채택안, 발행 채널 | 어디에 언제 발행할지 (파이프라인 밖) | [ ] |

## 2. 단계별 스위치

파이프라인 단계마다 **자동 / 사람 승인 / 사람만** 중 하나를 고르고 이유를 한 줄 적는다.

| 단계 | 자동 | 사람 승인 | 사람만 | 이유 (한 줄) |
|---|---|---|---|---|
| 입력(신제품 정보) 준비 | | | | |
| 리서치 리포트 작성 | | | | |
| 콘텐츠 초안 작성 | | | | |
| 검수 판정 | | | | |
| FAIL 초안 수정 (1회) | | | | |
| 2연속 FAIL 이후 처리 | | | | |
| PASS 초안의 채택 | | | | |
| 위키 회수 | | | | |
| 발행·광고 집행 | | | | |
| 비용·로그 점검 | | | | |

- 자동: 사람이 보지 않아도 진행. 결과만 로그로 남긴다
- 사람 승인: AI가 만들고 사람이 보고 통과시켜야 다음으로 간다
- 사람만: AI가 하지 않는다

## 3. 근거로 삼은 것

이유를 적을 때 참고한 사례나 오늘의 실행 결과를 적는다. 예: "함정 1건에서 검수자가 면역력 문장을 잡았다", "정보가 없으면 자동화도 채우지 못했다", "완전 자동 콘텐츠는 검수 없이 배포되면 품질이 무너진다는 사례".
