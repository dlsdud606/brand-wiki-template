# [브랜드명] 브랜드 위키 lint

파일을 수정하지 않고 점검 결과만 보고한다. `PASS`, `FAIL`, `확인 필요`를 구분하며 FAIL 항목에는 파일 경로와 해당 문장을 붙인다.

## 1. raw 점검

- `raw/`의 기존 파일이 수정·삭제·이동되지 않았는지 확인한다.
- 새로 추가된 raw 파일에 출처와 수집일이 있는지 확인한다. 이미지·엑셀처럼 첫 줄을 쓸 수 없는 파일은 `raw/README.md` 표에 있어야 한다.

## 2. 위키 근거 점검

- `01_knowledge/`의 사실 문장마다 `raw/` 경로가 붙어 있는지 확인한다.
- 제품 사실(함량·용량·월령·가격·인증·보관)이 `deliverables/research/asset-transcripts/`의 판독 값, 또는 신제품소개서 값과 일치하는지 확인한다. 다르면 FAIL.
- 자료마다 값이 다른 항목(출시일·가격·구성)이 `[확인 필요]`로 남아 있는지 확인한다. 한쪽 값을 사실로 쓰면 FAIL.
- 2025년 자산에서 가져온 가격·구성에 자산 날짜가 붙어 있는지 확인한다.
- 페르소나·고객 문장이 「가설」 표시 없이 사실처럼 쓰였으면 FAIL. 이 위키에는 후기 원본이 없다.

## 3. 승인 표현 점검

- `01_knowledge/brand/approved-claims.md` 승인 표의 각 행에 ID·근거·확인일·승인자·일자·유효기간이 모두 있는지 확인한다. 빈 칸은 `확인 필요`.
- 카피·초안의 효능·운영 표현 문장에 `[근거: C-xx]`가 없거나, 승인 표에 없는 ID를 썼으면 FAIL.
- 후보 표(`R-xx`)가 `deliverables/` 밖, 특히 `01_knowledge/` 안에 있으면 FAIL. 후보는 리포트에만 둔다.

## 4. 성과 데이터 점검

- 조회수를 구매·전환 성과로 표현했으면 FAIL.
- 기간이 다른 이벤트를 총 조회수로 비교했으면 확인 필요. 비교는 일평균으로 한다.
- 원본 게시기간 분모와 양끝 날짜 포함 달력일수 분모를 혼용했거나 원본 행을 추적할 수 없으면 FAIL.
- 조회수만으로 최적 할인율·예상 전환율·매출·ROI를 단정했거나 과거 혜택을 현재 확정 조건으로 썼으면 FAIL.

## 5. 심의·문체

- 질병·치료, 의학적 효능, 안전 단정, 즉시 인과 표현이 카피 초안에 있으면 FAIL.
- 최고·1위·유일·최초는 주최·연도·출처가 모두 없으면 FAIL.
- 말투·호칭·표기는 `01_knowledge/brand/tone-and-manner.md` 기준으로 보고한다.

## 6. 개인정보

- 개인 이름, 전화번호, 이메일, 리뷰어 ID가 위키·초안에 있으면 FAIL.

## 7. 채널 규격

- 초안의 크기·장 수·글자 수가 `05_channels/`의 해당 채널 문서와 맞는지 보고한다.
