# 숏폼 영상 문법 (릴스·쇼츠·틱톡)

릴스·쇼츠·틱톡 영상의 콘티·편집 기준. 사용자 지정(2026-10-13): 「실제 숏폼 문법처럼 사용 장면을 속도감 있게」. 브리프가 컷 수·컷 길이를 사용자 답변으로 정하지 않았다면 이 기준이 기본값이다. 위키의 심의·표시사항·아동 연출 규칙이 항상 우선한다.

## 리듬

| 항목 | 기준 |
|---|---|
| 첫 1초 | 사용 장면 한가운데에서 시작 (손이 제품을 집는 순간, 따는 순간, 마시는 순간). 로고·정적 제품 컷·설정 샷·느린 도입으로 시작하지 않음. 첫 프레임이 피드 미리보기 역할 |
| 컷 길이 | 0.5~1.5초. 15초면 10~16컷. 끝 화면을 빼면 2초 넘는 컷은 이유를 적음 |
| 금지 리듬 | 3초 고정 컷 반복, 느린 푸시인만으로 버티는 컷, 같은 샷 크기 연속 |
| 끝 화면 | 제품 컷 1.5~2초 이내 |
| 루프 | 마지막 컷 동작이 첫 컷으로 자연스럽게 이어지게 설계 (재시청 유도) |

## 장면 짜는 법

- **행동 단위로 끊기**: 꺼내기 → 쥐기 → 열기 → 마시기 → 내려놓기처럼 동사 하나에 컷 하나. 동작 중간에 자름(cut on action)
- **연결**: 손 동작·모양·방향이 이어지는 매치 컷, 같은 구도 점프컷, 휩 팬·손으로 화면 가리기 같은 짧은 전환. 디졸브·페이드는 끝 화면에만
- **시점**: 부모 시점 POV, 손 클로즈업, 탑뷰, 눈높이 핸드헬드. 스튜디오 광고 톤이 아니라 폰으로 찍은 듯한 자연광·생활 공간
- **크기 변화**: 와이드 ↔ 클로즈업 교차. 같은 소스 안에서 1.05~1.
- **비트 싱크**: BGM 템포 기준 비트표를 만들고 컷 전환·자막 등장을 비트에 맞춤

## 자막

- 한 화면 한 메시지. 컷이 빨라도 자막 블록은 최소 1.5초 유지하고, 글자가 많으면 더 길게. 여러 컷에 걸쳐 같은 자막을 유지할 수 있음
- 브리프의 자막 구조(리드·헤드·본문 등)와 원본 말투를 유지. 자막 위치는 안전 영역 안에 고정해 컷이 바뀌어도 흔들리지 않게

## AI 생성으로 만들 때

- 생성 모델은 클립당 최소 길이가 있으므로 **클립을 생성해 편집에서 0.5~1.5초씩 잘라 쓰는** 방식으로 설계. 한 클립에서 여러 컷을 뽑음
- 콘티에 `컷 수`와 `생성 클립 수`를 따로 적고, 컷마다 소스 클립 ID와 in/out 초를 연결
- **생성 방식은 브리프의 Q7-a 답을 따름**: ① text-to-video ② Codex 첫 프레임 이미지 → Higgsfield image-to-video(시작 프레임 `start_image`). ②는 컷마다 첫 프레임 프롬프트와 저장 경로(`assets/frame_<클립>.png`)를 먼저 넘기고, 사용자가 Codex에서 만든 이미지를 확인한 뒤 업로드해 생성. 같은 인물·같은 제품 유지와 첫 1초 구도 확인에 유리하고 Codex 단계가 하나 늘어남.
- **패키지 우선(2026-10-14 사용자 지정)**: 제품이 나오는 첫 프레임은 패키지 누끼를 첨부해 인쇄 정면이 보이게 만들고, 영상 프롬프트에 「패키지 인쇄 유지」를 넣음. 생성 뒤 인쇄가 빠진 클립은 Genjutsu(`hf_mult_replace_object`)로 교체. 목업 패키지면 끝 화면 구석에 작은 글씨로 연출 고지. 자동화는 `../../product-reel/`
- **패키지 물리 정합(2026-10-14 사용자 지적)**: 따르기·마시기처럼 개봉하는 장면에서 생성 모델이 떼어낸 캡을 파우치 옆에 붙여 그린다. 첫 프레임 문구에 「캡은 닫혀 있거나 화면에 없음」을 넣고(`reel.yaml package.integrity`), 생성 뒤 `check/패키지확인.md`의 캡·스파우트·형태 열에서 확인한다. 이 오류는 패키지 교체(Genjutsu)로 고쳐지지 않으므로 컷에서 빼거나 다시 만든다
- Kling 멀티샷은 프롬프트에 「Shot 1 / Shot 2」를 쓰는 것만으로는 켜지지 않음(생성 기록 `multi_shots: false` 확인). 샷 분리가 필요하면 멀티샷 옵션 또는 단일 샷 클립으로 나눔
- 멀티샷을 지원하는 모델이면 한 클립 안에 여러 샷을 묘사하는 프롬프트 가능. 모델·길이·크레딧은 생성 전 도구에서 확인하고 총량 브리핑 후 승인

## 콘티 산출물

1. 비트·컷 표: 시작–끝 초(소수 첫째 자리), 컷 길이, 동작(동사), 샷 크기, 카메라, 전환, 자막, 소스 클립 ID, in/out
2. 생성 클립 표: 클립 ID, 길이, 프롬프트, 뽑을 컷
3. 편집 지시: 펀치인 위치, 비트 싱크 지점, 루프 연결
4. 자체 점검: 첫 1초에 사용 장면이 나오는가, 평균 컷 길이, 2초 넘는 컷 목록과 이유

## 속도보다 우선하는 것

- 아이가 급하게 벌컥 마시기, 땀 흘리는 장면처럼 갈증 해소·수분 보충으로 읽히는 연출 금지
- 표시사항과 충돌하는 연출 금지 (예: 직사광선, 부푼 파우치, 개봉 후 오래 둔 제품)
- 아이 나이 특정, 안전·흘림 방지 주장으로 읽히는 클로즈업 금지
- 생성·목업 이미지에는 연출 고지 유지. 연출 고지는 끝 화면 구석에 작은 글씨로 둔다(사용자 지정 2026-10-14). 전 구간 화면 고지는 요구하지 않는다
