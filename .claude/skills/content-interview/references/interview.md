# 기획 인터뷰 기준

## 질문 방식

현재 요청의 답을 먼저 추출해 「정해진 내용: … / 확인할 내용: …」를 짧게 표시한다. 상품·채널을 지정했다면 다시 고르게 하지 않는다.

새 요청마다 「지난 기준인 새 스토리·원본 말투·원본 헤드와 서브 구조·페르소나 반영을 이번에도 적용할까요?」를 묻는다. 선택지는 「그대로 적용 / 일부 변경」이며 자유 답변도 받는다. 현재 요청에서 이미 기준을 명시했거나 「지난 기준대로」라고 답했다면 확인된 것으로 기록하고 재질문하지 않는다.

질문 도구가 있으면 1~3문항씩 선택지와 자유 답변을 제공한다. 비동기 질문은 실제 답변을 기다리고 미정 선택에 의존하지 않는 자료 탐색만 진행한다. 도구가 없으면 채팅으로 질문하고 답변을 기다린다. 질문 기능이 없는 하위 에이전트는 질문·미정 항목을 주 대화로 반환하며 주 에이전트가 사용자에게 묻는다.

아래는 체크할 차원이다. 모든 문항을 매번 따로 질문하지 않고 이미 답한 항목은 생략한다. 새 자동화 요청에서는 아직 정해지지 않은 선택을 실제로 질문한다.

## 인터뷰 항목

| ID | 질문 | 선택·답변을 적용할 곳 |
|---|---|---|
| Q1 상품·목적 | 어떤 상품으로 어떤 결과를 원하시나요? 상품 선정이 필요하면 후보를 골라드릴까요? | 지정 상품 또는 위임받은 선정. 인지·전환·재구매 목적과 기획만/제작까지 범위 |
| Q2 페르소나 | 누구에게 말을 걸까요? 위키 고객 가설이나 직접 정한 고객을 알려 주세요. | 해당 상품에 맞는 부모·온가족 등 후보. 고객의 관심·망설임·정보 우선순위 |
| Q3 새 스토리 | 원본과 다른 어떤 상황·메시지로 만들까요? 추천이 필요하면 후보 3개를 드릴게요. | 새 상황·앵글·핵심 메시지. 효능이나 문제 해결은 근거 없이 설정하지 않음 |
| Q4 말투 | 어떤 원본의 말투를 유지할까요? 해당 상품 원본을 우선하는 안을 제안합니다. | 상품·원본 경로·예문. 헤드·해요체 설명과 권유·합쇼체 안내 유형 |
| Q4-a 핵심 카피 출처 | 헤드·리드 같은 핵심 카피를 원본에 있는 문장에서 가져올까요? 원본 후보 문장을 보여 드릴게요. | 원본 문장 그대로 / 원본 문장 일부 변형 / 새로 작성. 슬롯별 채택 원문과 원본 경로. 위험 표현이 든 원문은 「원문 사용, 발행 전 확인 조건」 선택지로 제시 |
| Q5 헤드·서브 구조 | 헤드와 아래 서브, 본문·배지·사진 위치도 원본 그대로 유지할까요? | 원본 유지 / 지정 요소만 유지 / 새 구조. 화면별 기준 원본과 슬롯 순서·줄바꿈 |
| Q6 채널·수량 | 카드뉴스·상세·팝업·카카오·영상 중 무엇을 몇 개 만들까요? | 채널·장 수·페이지 수·길이·규격. 요청하지 않은 채널을 자동 추가하지 않음 |
| Q7 운영·자산 | 가격·혜택·일정·상품 URL과 제품 사진이 정해졌나요? | 확정 / 미정 / 제외. 과거 값을 현재 값으로 쓰지 않음. 사진·촬영·합성·생성 사용 범위 |
| Q7-a 영상 생성 방식 | 영상을 만들 때 텍스트만으로 생성할까요, Codex로 첫 프레임 이미지를 만든 뒤 그 이미지로 영상을 생성할까요? | text-to-video / Codex 첫 프레임 → Higgsfield image-to-video. 후자는 컷별 첫 프레임 프롬프트·저장 경로를 브리프에 기록. Codex 실행은 사용자 또는 Codex 세션 몫. 제품이 나오는 장면은 패키지 누끼를 첨부한 첫 프레임 → image-to-video를 추천안으로 제시(`product-reel`) |
| Q8 실행·비용 | 이번에는 기획·카피까지인가요, 실제 이미지·영상까지인가요? 제작비 한도가 있나요? | 실행 범위와 비용 한도. 유료 호출 전 구체적인 총량 승인 별도 확인 |

필수 선택은 상품, 목적·실행 범위, 페르소나, 핵심 이야기, 말투·구조 기준, 핵심 카피 출처, 채널이다. 사용자가 「추천해줘」「알아서 정해줘」라고 명시한 항목은 근거 있는 추천으로 채울 수 있으며 추천으로 기록한다. 무응답을 위임으로 취급하지 않는다. 운영 값이 미정이라도 계획은 만들 수 있으나 실제 게시·발송·혜택 카피는 필요한 값이 채워지기 전까지 보류한다.

상품 URL·게시 일정·가격은 그 값에 의존하지 않는 로컬 검수용 이미지·영상 초안을 막는 선행조건이 아니다. 미정 값을 만들지 않고 해당 CTA 연결·혜택 문구·발행·발송만 보류한다. 현행 표시사항이 미확정이면 제품 정보 요약과 확인용 초안은 만들되 발행본의 필수 표시사항 완료로 판정하지 않는다.

장 수·페이지 수·규격·영상 길이가 미정이면 기획 초안에는 미정으로 남길 수 있다. 실제 제작에 들어가기 전에는 해당 값을 사용자 답변이나 명시적으로 위임받은 추천으로 확정한다. 이전 캠페인의 수량·규격을 임의로 적용하지 않는다.

## 핵심 카피 출처 질문 (Q4-a)

사용자 지정(2026-10-13): 새로 지은 카피가 AI처럼 읽힌다는 지적에 따라, 핵심 카피를 원본에서 가져올지 매 캠페인 질문한다.

- 질문 전에 선택 상품의 판독 문서(`deliverables/research/asset-transcripts/<상품>.md`)와 원본 이미지에서 **원본 카피 후보**를 슬롯별(리드·헤드·본문·카드 소제목)로 3~6개 뽑아 원본 경로와 함께 보여 준다
- 후보마다 위험 표시를 붙인다: 사용 가능 / 확인 필요(현행 값 확인이 필요한 수치·함량·원산지·인증) / 사용 불가(질병·효능·편식·최상급·출시·과거 혜택). 사용 불가 문장은 후보에서 빼고 이유만 적는다
- 「진하게」「원물 가득」「맛있게」 같은 감각·묘사 표현과 브랜드가 이미 발행한 표현은 「사용 가능」으로 둔다. 근거 확인 대상으로 묶지 않는다 (사용자 지정 2026-10-14)
- 선택지: 「원본 문장 그대로」 / 「원본 문장 일부 변형(위험 부분만 바꿈)」 / 「새로 작성」. 확인 필요 문장을 고르면 「원문 사용, 발행 전 확인 조건」으로 기록한다
- 답은 브리프의 「핵심 카피 출처」 항목에 슬롯별 채택 원문·원본 경로·조건으로 남기고 copywriter에 전달한다

## 이벤트 요청 추가 차원

행사에는 [이벤트·혜택 기획](event-benefits.md)의 목표/추천 위임, 혜택 종류·예산·가격/마진·재고·쿠폰 조건·운영기간·노출 계획을 묶어 질문한다. 답한 내용은 재질문하지 않는다. 원본 조회수 비교와 후보/운영안은 브리프에 연결하며 미정 운영값이 로컬 기획·시안 전체를 막지 않도록 한다.

## 누적 기준 적용

| 사용자 기준 | 매 요청에서 유지할 방식 |
|---|---|
| 원본 기반 새 콘텐츠 세트 | 새 상황·장면·구성을 만든다. 과거 캠페인 재현이나 크기 변환만으로 완료하지 않는다. 핵심 카피 문장은 Q4-a 답에 따른다 |
| 원본 말투 그대로 | 선택 상품의 헤드 길이·종결·설명·권유·안내 예문을 대조한다 |
| 헤드 아래 서브 등 구조 동일 | 화면마다 원본의 텍스트 자리·정보 위계·정렬·줄바꿈·배지·CTA 유무를 기록한다 |
| 고객 페르소나 반영 | 고객 가설·검증된 고객 정보를 구분하고 관심·망설임에 답하는 문장을 연결한다 |
| 캠페인별 선택 | 특정 상품·외출 이야기·5장·20초를 고정 기본값으로 만들지 않는다 |

## 제작에 넘기는 계약

채워진 답변과 위임받은 선택을 한 번 요약해 보여 준다. 필요한 답변이 있으면 불필요한 추가 승인 없이 요청 범위의 작업을 진행한다. 중요한 모호함만 해당 항목을 재질문한다.

구조 유지 답변을 받으면 화면마다 `reference_path`, `visual_check_status`, `top_label`, `headline`, `subcopy_below_headline`, `body`, `emphasis`, `image_area`, `badge`, `cta`, `line_breaks`를 저장한다. 없는 요소는 `없음`이다. 이미지를 직접 읽어 위치를 확정하며 채널 문서만으로 위치를 추측하지 않는다. 형태를 유지하되 출시·할인·효능 등 내용은 이번 사실로 치환한다.

카피별로 `문장 / 제품 근거 / 페르소나 관심 / 원본 말투 / 배치 슬롯`을 연결한다. 인터뷰 답변이 서문에만 있고 실제 카피·배치가 이전 기준이면 반영 완료가 아니다.

## 수정과 재개

동일 캠페인에서 「말투는 원본처럼」「구조도 동일하게」「페르소나 반영」 같은 추가 메시지는 답변을 보완한다. 브리프 버전을 올리고 영향받는 카피·비주얼·검수를 갱신한다. 이전 답변을 지우거나 전체 인터뷰를 새로 시작하지 않는다.

새 상품·새 캠페인·새 목적에는 새 인터뷰를 시작한다. 재사용할 답변이 현재 요청에 명시되면 확인된 기준으로 가져오고 변경된 선택만 묻는다. 예약·비대화 실행에서 필요한 답이 없으면 인터뷰 대기 기록과 질문을 반환한다.
