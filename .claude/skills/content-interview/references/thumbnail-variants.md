# 채널별 썸네일 변주

## 진입과 입력

“채널별 썸네일”, “표지를 다양하게”, “여러 디자인”, “A/B안” 요청에 적용한다. 기획만 요청하면 후보표·브리프까지만 만든다. 에이전트 기능 수정 요청은 설정을 수정하며 이미지 생성이나 새 캠페인 인터뷰를 시작하지 않는다.

같은 캠페인은 기존 브리프·확정 카피·제품 사진·원본 구조 계약·생성 승인 범위를 재사용한다. 새로 필요한 채널/노출 위치, 안 수, 변경 범위만 확인한다. 사용자가 연출을 맡겼으면 근거를 적고 추천한다. 수량 미지정 시 채널당 3개 방향을 **기획 제안**하되 실제 생성 수량·비용 승인으로 간주하지 않는다. 이미 승인한 수량·도구·재시도 범위는 다시 묻지 않는다.

## 1. 노출 위치와 규격 결정

`05_channels/thumbnail.md`와 해당 채널 문서, 캠페인 브리프를 함께 읽는다. 상품 목록 이미지, 이벤트 진입 썸네일, 팝업 이미지, 피드·카드뉴스 표지, 영상 커버는 서로 다른 화면이다. 썸네일 요청만으로 본문 카드 전체나 영상을 새로 만들지 않는다.

| 위치 | 위키의 기존 제작/관찰값 | 설계 초점 |
|---|---|---|
| 상품 목록 | 350×350 또는 1000×1000 | 실제 구성과 제품 식별, 카피 없는 원본이면 유지 |
| 랜딩·이벤트 진입 | 1000×1000 | 상품과 이벤트 핵심, 상세 설명은 연결 페이지로 |
| 팝업 | 400×476 | 짧은 헤드·아래 서브·진입 CTA, 실제 계약의 슬롯 유지 |
| Instagram 피드·카드 표지 | 1080×1350 | 축소해도 읽히는 첫 메시지와 제품 |
| 카카오 푸시 | 800×600 | 짧은 정보와 제품, 메시지 본문과 조건 일치 |

이 값은 기존 자산의 관찰·제작값이며 플랫폼 최신 필수 규격이 아니다. 사용자 지정 규격을 우선하고 실제 노출 위치·잘림 영역을 기록한다. 영상 커버·새로운 채널은 프로젝트 규격과 표시 영역부터 확인한다. 플랫폼 최신 규격을 보장해야 하는 작업은 공식 문서를 확인하고 출처·확인일을 남긴다.

## 2. 서로 다른 방향 설계

채널별 후보마다 고객이 처음 볼 정보와 시각적 차이를 적는다. 상품에 맞는 방향을 골라 조합하며 아래 이름이나 구성을 모든 상품에 강제하지 않는다.

- 제품 중심: 실제 패키지를 크게, 여백과 간결한 정보.
- 원료·구성 중심: 확인된 원료 또는 실제 구성품으로 선택 기준 설명.
- 사용 장면 중심: 부모 페르소나의 관심을 반영한 보관·준비 장면. 실제 고객 조사로 표현하지 않는다.
- 혜택 중심: 확정된 할인·기간 강조. 제안 조건은 제안 상태를 유지한다.
- 카피 중심: 확정 헤드의 크기·줄바꿈·대비로 메시지 강조. 무문구 상품 썸네일에는 적용하지 않는다.

동일 채널의 후보는 구도, 제품의 크기·위치, 배경 장면, 정보의 시각적 강조 중 적어도 두 요소가 구별되게 설계한다. 색상만 교체하거나 같은 파일을 리사이즈한 결과를 별도 디자인으로 세지 않는다. 단, 사용자가 색상만 변경하도록 범위를 좁혔으면 그 요청을 따른다.

고정: 제품 사실·실제 패키지·브랜드 팔레트·확정 혜택/기간·말투·헤드 아래 서브 등 구조 계약. 변주: 계약 안의 배치·여백·스케일·사진 연출·정보 강조. 새로운 슬롯·문구·구조 변경은 후보표에서 구분하고 사용자 위임 범위 안에서 결정한다. 카피 변경이 필요하면 copywriter가 근거를 확인해 확정 카피에 반영한 뒤 제작에 전달한다.

스타일 프리앰블은 같은 방향의 채널 세트 안에서 고정한다. 서로 다른 방향은 브랜드의 고정값을 공유하고 장면·구도 지시를 별도로 둔다. 프리앰블을 고정한다는 이유로 모든 후보를 같은 장면으로 만들지 않는다.

## 3. 후보표와 제작량

`deliverables/content/<건명>/thumbnails/기획.md`에 아래 표와 추천 이유를 쓴다.

| ID | 채널·노출 위치 | 규격·표시 영역 | 고객 관심 | 방향·두 가지 차이 | 고정 카피 경로·슬롯 | 기준 원본·제품 사진 | 변경 허용 범위 | 상태 |
|---|---|---|---|---|---|---|---|---|

ID 예: `instagram_A`, `popup_B`. 디자인 방향 수, 생성 배경 수, 최종 출력 수를 따로 센다. 3채널×3안이면 출력은 9개지만 공용 배경 3장+합성 9개일 수 있다. 공유 여부를 브리프에 기록하고 재시도도 총량에 포함한다.

기존 사진·배경·코드 합성으로 만들 수 있으면 그 방식으로 진행한다. 새 배경이 필요하면 사용자 지정 도구(현재 이미지 기본: Codex GPT 이미지 생성), 수량·재시도 한도·확인 가능한 비용을 제시한다. 비용을 모르면 미확인으로 적는다. 기존 승인 범위에 포함되면 이어서 제작하고, 범위를 늘리는 생성만 추가 확인한다.

## 4. 제작과 출력

1. 최종 상품 인쇄·로고는 실제 제품 자산을 사용한다. 새 배경은 제품 패키지·로고·한글 없이 만들고 합성 공간을 확보한다.
2. 실제 제품 사진과 확정 카피를 HTML/CSS 등 편집 가능한 레이어로 배치한다. 흰 배경 사진을 투명 누끼로 표기하지 않는다. 저해상도 원본은 선명도 한계를 기록하고 필요한 경우 고해상도 자산을 요청한다.
3. 채널별 레이아웃을 다시 구성한다. 원본을 그대로 늘리거나 자르면서 패키지·문구를 훼손하지 않는다. 결과는 지정 픽셀 크기의 PNG/JPG로 출력한다.
4. `preview.html`에 채널별 A/B/C를 같은 표시 크기로 나란히 배치한다. ID·방향·차이·추천 이유·검수 상태를 표시하고 각 최종 파일을 열 수 있게 한다. 미제작 방향은 텍스트 제안으로 표시한다.
5. `manifest.json`에 브리프 버전, ID, 채널, 방향, 규격, 카피/사진/배경 출처, 생성 여부·도구, 편집 소스·최종 파일 경로, 상태를 남긴다. `검수.md`에 실제 출력 검수 결과를 적는다. 경로는 해당 캠페인 기준 상대 경로로 연결한다.

## 5. 검수와 선택

brand-auditor는 실제 파일을 열어 규격·작은 화면의 가독성·잘림·헤드/서브 순서·패키지 중복/색 변형/인쇄·날짜/혜택 일치와 후보 간 차이를 확인한다. 구성 제안만 있거나 이미지 확인이 불가능하면 제작 완료/PASS로 표시하지 않는다. 동일 후보가 2회 연속 FAIL이면 그 후보의 자동 수정을 멈추고 이유와 대안을 보고한다.

추천은 브랜드 적합성·가독성·고객 관심에 대한 판단으로 설명한다. 과거 이벤트 조회수로 특정 썸네일의 CTR·전환 우위를 단정하지 않는다. A/B 테스트를 계획하면 같은 채널·조건에서 비교할 노출/클릭과 측정 기간을 정하고, 실측 전 결과는 가설로 남긴다. 여러 디자인 방향을 동시에 바꾼 탐색과 한 변수만 바꾼 실험을 구분한다.
